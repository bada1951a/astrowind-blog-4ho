## 1. [Opening Story/Problem]

渋谷のITベンチャー企業の会議室で、午後から始まる重要クライアント向けの競合リサーチ資料を急ぎ作成していた時のことだ。開発チームから上がってきた膨大な非構造化テキスト（箇条書きの雑多なメモ、PDFからのコピペ、バラバラなフォーマットの仕様書など）を、今すぐきれいなMarkdownの表やCSV形式に整理する必要があった。

「よし、AIにこのテキストを渡して表形式に整理してもらおう」と軽い気持ちで「以下のテキストを分かりやすく表にまとめて」とChatGPTに放り投げた。すると、あろうことかAIは存在しないダミーの列勝手に生成したり、古いライブラリの構文やすでに廃止されたAPIエンドポイントの仕様を交ぜ込んだ誤った表を出力し、エラーが続出する事態に発展した。締め切りまで30分を切る中、パニックになりかけたその瞬間、私は「プロンプトの構造自体に問題がある」と気づき、即座に**Few-Shotプロンプト（少数例提示プロンプト）**の設計へと切り替えた。

## 2. [Root Cause / Architecture]

なぜ単純な指示（Zero-Shot）では、非構造化テキストから正確なテーブルデータを抽出できないのだろうか。その根底にあるのは、AIが「文脈の揺れ」や「暗黙のフォーマット」を正確に予測しきれないという限界だ。

特に技術文書やバラバラのメモを処理する場合、AIは確率的に「もっともらしい嘘（ハルシネーション）」を生成しやすい。ここで有効なのが、**Few-Shotプロンプトアーキテクチャ**である。

- **Zero-Shotの限界:** 「表にして」という曖昧な指示では、出力されるカラム名やデータ型が実行のたびに変わり、自動化パイプラインに組み込めない。
- **Few-Shotの仕組み:** 「入力データの例」と「期待される正しい出力例」をプロンプト内に1件から数件あらかじめ提示（例示）することで、AIが出力の構造（Schema）を強力に学習し、揺るぎない精度でデータを抽出できるようになる。

## 3. [Master Prompt Template]

実務でそのままコピー＆ペーストして使える、非構造化テキストからのデータ抽出用マスタープロンプトテンプレートを公開する。ChatGPTやClaude、Geminiの**システムプロンプト**またはユーザー入力の冒頭に設定して使用してほしい。

```markdown
# 役割
あなたは極めて正確なデータエンジニア兼AIアナリストです。
以下の「入力データ（非構造化テキスト）」を解析し、指定された「出力フォーマット（Markdownテーブル）」に厳密に従ってデータを抽出・変換してください。

# 制約事項
1. 入力データに存在しない情報は勝手に捏造（ハルシネーション）せず、該当項目がない場合は「N/A」と記載してください。
2. 出力は余計な挨拶や解説文を含めず、Markdownのテーブル形式のみを出力してください。
3. 提供する「例（Few-Shot Example）」の構造とデータ型を完全に模倣してください。

# 抽出ルール
- カラム1: 項目名 (String)
- カラム2: ステータス (String: 進行中 / 完了 / 凍結)
- カラム3: 担当チーム (String)

# 少数例提示 (Few-Shot Examples)
---
[入力例 1]
プロジェクトAは現在進行形で、渋谷チームが担当している。来週リリース予定。
[出力例 1]
| 項目名 | ステータス | 担当チーム |
| :--- | :--- | :--- |
| プロジェクトA | 進行中 | 渋谷 |
---

# 実際の入力データ
[Insert Unstructured Text Here]
```

## 4. [Practical Variations / Safety Tips]

実務の現場でこのプロンプトをさらに強靭にするための応用テクニックと安全運用のコツを紹介する。

- **Claudeのアーティファクト活用:** 長大な表データを扱う場合は、Claudeのアーティファクト機能を併用すると、生成された表をプレビューしながらその場でCSVとしてダウンロードできるため非常に効率的だ。
- **JSONスキーマの併用:** テーブルだけでなく、後続のPythonスクリプトで自動処理したい場合は、出力フォーマットをMarkdownからJSONに変更し、````json`ブロックで囲むよう指示するとエラー率が激減する。
- **トークン節約のコツ:** 入力テキストが数万文字に及ぶ場合は、テキストをチャンク（分割）し、プロンプトのコンテキストウィンドウを圧迫しないように前処理を行うこと。

## 5. Frequently Asked Questions

Q: Few-Shotの例（サンプル）はいくつ提示するのが最も効果的ですか？

A: 通常の表抽出であれば、1件から3件の正確な入出力ペアを提示するだけで十分な精度が得られます。複雑な例外処理が含まれる場合のみ、パターンごとに例を増やしてください。

Q: AIが勝手にカラムの項目を省略してしまう場合はどうすればいいですか？

A: 制約事項セクションに「入力データ内のすべてのエンティティをもれなく行として抽出すること。省略は厳禁です」と明確に追記することで、データ抜けを防ぐことができます。

Q: プロンプトの指示に従わず、前置きの挨拶をどうしても出力してしまう時の対策はありますか？

A: システムプロンプトまたはプロンプトの最尾に「出力の最初の文字は必ずMarkdownのテーブルのパイプ（|）から始めること」と指定すると、余計な挨拶を完全に排除できます。
